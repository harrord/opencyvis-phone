## 调研：Agent 能否直读 /sdcard/Download 下的 txt

结论：**当前不能**，三处断点：
1. `AndroidManifest.xml`（main flavor）无任何存储权限（无 READ_EXTERNAL_STORAGE / READ_MEDIA_* / MANAGE_EXTERNAL_STORAGE）。
2. LLM 只暴露单一工具 `phone_action`（`llm/ToolSchema.kt`），`action/Action.kt` 的 17 个 action_type 全是 UI 操作，无 read_file / shell。
3. `aidl/ai/opencyvis/backend/IPrivilegedService.aidl` 只有输入注入、虚拟显示、截屏、task 查询移动、forceStop，无文件读取也无通用 shell 通道。

补充事实：Android 11+ 分区存储下，Download 目录的 txt 属非媒体文档，READ_EXTERNAL_STORAGE 对其无效，"公开目录任意 App 可读"的说法不成立。

推荐改造方案（未实施）：给 IPrivilegedService 增加 `readTextFile(path, maxBytes)`（shell uid 2000 属 sdcard_rw，可直读 /sdcard），再封装为 Action `read_file` 并注册进 ToolSchema + Action.fromMap。替代方案有 MANAGE_EXTERNAL_STORAGE（权限重）和 SAF（需用户交互，无法凭文件名静默读）。

### 补充澄清（用户追问）

- 若已授予 MANAGE_EXTERNAL_STORAGE，权限层面成立，App 进程可直读；但仍需补 Action + ToolSchema，且该权限不含跨包 Android/data、Android/obb。只能跳设置页申请，不能弹窗。
- "shell 通道"含义澄清：指 **uid 2000 的进程身份**，不是执行 shell 命令。全项目只在 `DirectConnector.launchService()`（:240）用了一次 adb 命令 `CLASSPATH=<apk> app_process /system/bin ai.opencyvis.backend.PrivilegedServiceMain`，目的是拉起进程；之后全程是 Binder RPC（`IPrivilegedService`），由 shell 进程在自己 uid 下用 File API 读文件回传字符串。
- 三种特权后端：`SystemBackend`（system flavor，sharedUserId=android.uid.system，uid 1000）、`RemoteBackend` + ShizukuConnector、`RemoteBackend` + DirectConnector（无线调试自建，uid 2000）。`BackendDetector.detect()` 按此顺序探测。
- 用户已采纳三条实现约束：路径白名单、64KB 截断、UTF-8 失败回退 GBK。
- 决策建议：优先 App 进程直读（若 isExternalStorageManager），回落 shell 通道。

## 调研：Agent 能力全景审计 + 对标 2026-09 主流 Agent

### 现有能力核实结果（基于源码，非文档）

动作层已扩到 **19 个 action_type**（此前记录为 17，因本轮已确认 read_file/write_file 及 list_apps 均已落地）：
tap / long_press / open_app / list_apps / read_file / write_file / swipe / key_event / type_text /
wait / sleep / finish / fail / ask_user / handoff_user / note / remember / save_routine / notify

关键实现参数（后续改动勿踩）：
- `AgentEngine`: `maxSteps=100`、`MAX_HISTORY_MESSAGES=100`，**每步后 stripImagesFromHistory 剥离历史图片**（只留最近截图控 token）。
- `LLMClient`: `MAX_OUTPUT_TOKENS=1024`、`MAX_RETRIES=6`。
- `read_file` 路径白名单：仅 `/sdcard/Download`、`/sdcard/Documents`；`write_file` 只能写 `/sdcard/Download/OpenCyvis`（MediaStore，仅覆盖本应用创建的文件）。
- 提示词中英双份，`LlmPrompts` 内 SYSTEM_PROMPT / TOOL_DESC / PARAM_DESCS / GUARD / AGENT_FEEDBACK 五组均需同步。

已有但易忽略的工程细节（同类开源项目里属优势）：
VdAccessibilityService 注入 UI 元素树 bounding box、ScreenFingerprint 平均哈希判画面未变、
ActionRepeatGuard 拦重复输入/提交/近似点击、HandoffVisualDetector 黑帧判 FLAG_SECURE、
TaskDisplayGuard 任务逃逸救助、geofence + AlarmManager + BootReceiver 定时、Sherpa-ONNX 端侧 ASR、飞书/Telegram 远程操控。

### 主要缺口（对标结论）

P0：联网搜索/网页抓取、MCP 或任何工具扩展机制（工具硬编码在 ToolSchema，第三方不可扩展）、
代码执行/终端（方案书 9.3 明确禁止通用 shell 通道）、文档解析（PDF/Office/OCR）、任务规划分解（扁平 ReAct 无 plan/todo）。
P1：语义记忆检索（现为扁平 KV 全量注入）、跨会话记忆整合、上下文滚动摘要、子代理/多代理编排、
并行执行、危险动作二次确认、审计日志回放、成本预算控制、TTS、完整文件系统操作。
P2：通知读取、短信/通讯录/日历 API、剪贴板读、相机感知、系统事件触发、主动建议、多模态生成、benchmark 接入、prompt caching、多模型路由、跨设备协同。

### 架构建议（重要）

新增能力**不要继续堆 action_type**。`phone_action` 已承载 19 种语义，再堆会退化成不可维护巨枚举。
应在新增第 3~4 个非 GUI 能力之前，先把工具层重构为多工具注册制（先不接 MCP 也要有注册表）。
